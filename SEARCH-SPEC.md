# Техзадание: Поиск по сайту Prepra

Статус: согласовано (сессия дизайна через grill-me)
Связано: `ROADMAP.md` Phase 4

## Контекст

- Статический сайт Astro 5 (`output: 'static'`, `base: '/prepra'`), хостинг — GitHub Pages.
- Контент — markdown в `docs/`, 15 разделов, 177+ статей, загружается через content collections (`site/src/content/config.ts`).
- Сейчас в шапке стоит заглушка `site/src/components/layout/SearchInput.astro` — поле `readonly` с подсказкой «Ctrl+K». Её нужно заменить рабочим поиском.
- Интерактив — React-острова. Стили — Tailwind 3, иконки — Phosphor.
- Бэкенда нет, env-переменных нет. Поиск должен работать полностью на клиенте.

## Решение: build-time JSON-индекс + MiniSearch

Кастомный JSON-индекс генерируется на этапе сборки из content collections, лежит в бандле сайта. На клиенте — MiniSearch. Сетевых запросов нет, лоадер и длинный debounce не нужны.

## Требования

### 1. Генерация индекса (build-time)

- Источник: все статьи из content collections (все 15 разделов).
- Индексируемые поля на каждую статью:
  - `title` (заголовок),
  - `tags` (теги из frontmatter),
  - плюс метаданные для вывода: `section`, `slug`, URL статьи, `description`.
- Нормализация при генерации:
  - **Русский стемминг** — MiniSearch из коробки его не имеет. Нужен, чтобы «хуков» ≈ «хук», «hooks» ≈ «hook». Подключить стеммер/нормализацию для русского (и английского) на этапе построения индекса и при обработке запроса.
  - **Словарь транслитерации** популярных терминов (React→Реакт, JS→Джаваскрипт, TypeScript→Тайпскрипт и т.п.), расширяемый. Чтобы «Реакт» находил статью про React.
- Индекс должен попадать в публичный вывод (например, `site/public/search-index.json` или `dist/`) и подхватываться React-островом.

### 2. Клиентский поиск (MiniSearch)

- Поля: `title`, `tags`. Регистр игнорируется.
- Поиск срабатывает только на **полное слово**, не на префикс.
- Debounce при вводе ≤ 150ms (чтобы не перерисовывать список на каждый символ). **Без лоадера/спиннера**.
- Ранжирование:
  - Совпадение по тегу > совпадение по title.
  - Больше совпавших слов запроса → выше.
  - Tie-break: порядок `order` статьи внутри раздела, затем алфавит раздела.
  - Вывод максимум 5 статей.

### 3. Модальное окно (UX)

Структура сверху вниз:

1. Строка поиска.
2. **Pills** недавних запросов.
3. Вывод результатов (или пустое место).

#### Открытие

- Клик по полю поиска в шапке.
- Хоткей `Ctrl+K` (и `Cmd+K`).
- **Мобильные**: добавить иконку-лупу рядом с кнопкой бургер-меню в шапке. На мобильных модалка полноэкранная поверх сайта, закрытие — крестик. На десктопе — центрированное окно.

#### Поведение

- При открытии без запроса: строка поиска + список Pills + пустое место под результатами. Пустое место НЕ заменяется текстом «ничего не найдено», пока не было реальной попытки поиска.
- «Ничего не найдено» показывать только когда по итогам реального поиска результатов действительно нет.
- Клик по результату → переход на статью, модалка закрывается.

#### Pills (недавние запросы)

- Хранятся в `localStorage`.
- Максимум 8 штук, дедупликация: повторный запрос не дублируется, а поднимается вверх.
- Клик по пилюле → запускает поиск по этому запросу.
- Каждая пилюля удаляется индивидуально (крестик).
- **Запись в историю только при «коммите» запроса**: нажатие Enter, клик по результату, клик по тегу. Промежуточные символы при вводе в историю НЕ пишутся.

### 4. Интеграция с тегами

Клик по тегу в статье или в списке статей → автоматически открывается модалка с предзаполненным тегом в строке поиска и найденными статьями.

### 5. Клавиатура

- Стрелки ↑/↓ — навигация по результатам.
- Enter — переход к выбранному результату.
- Escape — закрыть модалку.

## Дизайн-код проекта

Все UI-компоненты поиска (модалка, строка ввода, Pills, результаты) обязаны соблюдать дизайн-код Prepra. Никаких произвольных цветов, скруглений, теней и шрифтов — только существующие токены и паттерны.

- **Цвета** — только токены Tailwind из `site/tailwind.config.js` (`canvas`, `surface`, `border`, `text`, `accent`, `pale-*`) и CSS-переменные из `site/src/styles/global.css`. Светлая/тёмная тема — через класс `.dark`, все цвета уже определены в обеих.
- **Шрифты** — только `font-sans` (JetBrains Mono), `font-mono` для акцентов/kbd. Заголовки — uppercase, `font-weight: 800`, без закруглений.
- **Стиль** — нео-брутализм проекта:
  - рамки `border-2 border-border` (чёрная в светлой теме, белая в тёмной),
  - скругления `rounded-none` (никаких `rounded-lg`/`rounded-xl`),
  - hover-эффекты в духе `.card-hover` (смещение `translate(-2px,-2px)` + жёсткая тень `4px 4px 0px var(--color-border)`), без мягких `box-shadow`.
- **Фоны** — `bg-canvas` для модалки, `bg-surface` для карточек результатов, `bg-surface-alt` для Pills/kbd.
- **Иконки** — Phosphor Icons (`@phosphor-icons/react`), как во всём проекте (лупа — `MagnifyingGlass`, крестик — `X`, стрелки — `ArrowUp`/`ArrowDown`).
- **Паттерны** — следовать существующим компонентам: инпуту `SearchInput.astro`, кнопкам `ui/Button.tsx`, бейджам `ui/Badge.astro`. Классы `badge-hover-*` из `global.css` использовать для hover-состояний тегов/pills.
- **Анимации** — плавные CSS-переходы (~100–300ms), допускается GSAP только если реально нужен; по умолчанию — CSS.
- **Адаптивность** — mobile-first, как в `Header.astro`/`SearchInput.astro` (`hidden sm:flex` и т.п.).

## Проверка

- `npm run build` собирается без ошибок TypeScript/схемы контента.
- Индекс генерируется в собранном выводе.
- Ручная проверка:
  - «Хук»/«Хуки»/«Hook»/«Hooks» находят статьи про хуки.
  - «Реакт» находит статью про React.
  - Тег «discriminated-unions» (слово-в-слово) находит статью с этим тегом.
  - Ввод промежуточных символов не засоряет Pills.
  - Ctrl+K, стрелки, Escape работают.
  - На мобильном (узком экране) модалка открывается по лупе и полноэкранна.
