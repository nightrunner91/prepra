# Типы данных и приведение типов

Форма заказа. Пользователь вводит цену, и поле возвращает строку `'100'`. Ты считаешь итог: `price + 10`, и получаешь `'10010'`. Никакой ошибки нет, JavaScript просто решил, что `+` со строкой означает склейку. Таких сюрпризов много, и почти все они объясняются двумя вещами: что значит значение и как движок приводит одно к другому. Без этого `typeof`, условия, сравнения и `NaN` превращаются в набор случайных правил. Эта статья про то, почему эти правила устроены именно так.

## Значения и ссылки

Все значения делятся на **примитивы** и **объекты**, и разница между ними проявляется при первом же присваивании.

Примитив копируется **по значению**. Каждая переменная получает свою копию, и изменение одной не касается другой:

```js
let price = 10;
let discounted = price;
discounted = 8;

console.log(price); // 10
```

Объект копируется **по ссылке**. Переменная хранит адрес объекта, а не сам объект, поэтому две переменные указывают на одно и то же:

```js
const cart = { items: 2 };
const order = cart;
order.items = 5;

console.log(cart.items); // 5
```

Это часто становится багом в React: ты взял состояние в переменную, поменял поле и думаешь, что работаешь с копией. Сравнение `===` для объектов тоже проверяет ссылки, а не содержимое: `{} === {}` даёт `false`, потому что это два разных объекта.

Заметь: спецификация говорит о поведении (значение или ссылка), но не о том, где движок хранит данные. Фраза «примитивы в стеке, объекты в куче» — упрощение реализации, на поведение оно не влияет.

## Семь примитивных типов

1. `number` — числа, включая `NaN`, `Infinity` и `-Infinity`.
2. `bigint` — целые числа произвольной длины (`123n`).
3. `string` — строки.
4. `boolean` — `true` и `false`.
5. `undefined` — значение не присвоено.
6. `null` — явное «ничего».
7. `symbol` — уникальный идентификатор.

Всё остальное — объекты, включая массивы и функции. Функция — это объект, который можно вызвать.

### `symbol` и `bigint`

`Symbol` даёт уникальный ключ, который не столкнётся с чужим. Это полезно, когда добавляешь служебное поле в объект, которым пользуешься не только ты:

```js
const id = Symbol('id');
const user = { name: 'Alice', [id]: 123 };

console.log(user[id]);          // 123
console.log(Object.keys(user)); // ['name'] — символ не попадает в перечисление
```

Встроенные символы вроде `Symbol.iterator` и `Symbol.toPrimitive` позволяют менять поведение объекта при итерации и приведении типов.

`bigint` нужен для целых чисел больше `Number.MAX_SAFE_INTEGER`, то есть больше 2^53 − 1:

```js
const huge = 9007199254740993n;
console.log(huge + 1n); // 9007199254740994n
```

`bigint` и `number` нельзя смешивать в арифметике: `1n + 1` выбросит `TypeError`.

## typeof и его особенности

`typeof` возвращает строку с названием типа:

```js
typeof 42;          // "number"
typeof 42n;         // "bigint"
typeof 'hello';     // "string"
typeof true;        // "boolean"
typeof undefined;   // "undefined"
typeof null;        // "object" ← историческая ошибка
typeof {};          // "object"
typeof [];          // "object"
typeof function() {}; // "function"
typeof Symbol();    // "symbol"
```

`typeof null === 'object'` — баг первой реализации: тип определялся по битовым меткам, и у `null` метка совпадала с меткой объекта. Исправить его уже нельзя, потому что миллионы страниц полагаются на это поведение.

На практике это ловит `if (typeof value === 'object') value.length`: для `null` условие истинно, и код падает. Для `null` используй строгое сравнение, а для массивов — `Array.isArray`:

```js
value === null;
Array.isArray([]); // true
Array.isArray({}); // false
```

## Явное приведение типов

Явное приведение делает код предсказуемым: ты сам решаешь, что получится, а не полагаешься на правила языка.

Форма вернула строку `'12px'` или пустое поле. Что будет, если превратить это в число?

```js
Number('42');       // 42
Number('');         // 0 ← пустое поле стало нулём
Number('  ');       // 0
Number(null);       // 0
Number(undefined);  // NaN
Number('12px');     // NaN
```

`Number` строгая: строка либо целиком число, либо `NaN`. Для валидации это удобно, потому что `NaN` сразу видно. А вот `parseInt` и `parseFloat` берут число с начала строки, пока могут:

```js
parseInt('12px');       // 12
parseInt('FF', 16);     // 255
parseFloat('3.14abc');  // 3.14
parseInt('abc');        // NaN
```

Так `Number('')` даёт `0`, а `parseInt('')` даёт `NaN`. Это разные функции с разными правилами, и путать их опасно. Основание у `parseInt` лучше указывать явно: `parseInt('08', 10)`.

Остальные конструкторы:

```js
String(42);         // "42"
String(null);       // "null"
Boolean(0);         // false
Boolean('hello');   // true
Boolean([]);        // true ← пустой массив истинен
```

## Неявное приведение и falsy

Неявное приведение происходит само, когда оператор ожидает другой тип. Удобно, пока правила знаешь.

**Оператор `+`** конкатенирует, если хотя бы один операнд — строка:

```js
5 + '5';    // "55"
true + '5'; // "true5"
```

**Арифметические операторы** (`-`, `*`, `/`, `%`) приводят операнды к числу:

```js
'5' - 3;       // 2
'5' * 2;       // 10
'hello' - 3;   // NaN
null + 5;      // 5 ← null становится 0
undefined + 5; // NaN
```

**Условия** (`if`, `&&`, `||`, тернарный оператор) используют булево приведение. Значения делятся на falsy и truthy. Falsy всего восемь:

- `false`, `0`, `-0`, `0n`;
- `''`;
- `null`, `undefined`;
- `NaN`.

Всё остальное — truthy, включая `'0'`, `'false'`, `[]` и `{}`.

Именно здесь чаще всего возникает баг в React. Представь список, который показывают, только если в нём есть элементы:

```jsx
{items.length && <List items={items} />}
```

Если `items` пуст, выражение вернёт `0`, а не `undefined`. React выведет `0` на экран, потому что число — это текст, который надо отрисовать. Исправление: `items.length > 0 && <List ... />` или тернарный оператор.

## ToPrimitive и Symbol.toPrimitive

Когда объект участвует в операции, которая требует примитива (конкатенация, арифметика, сравнение), JavaScript вызывает внутренний алгоритм **ToPrimitive**. Он получает подсказку (hint) о том, какой примитив ожидается:

- **`string`** — для `String(obj)`, шаблонных строк, `alert(obj)`;
- **`number`** — для арифметики (`-`, `*`, `/`), `Number(obj)`, сравнений `<` и `>`;
- **`default`** — для `==`, и для `+`, где ни один операнд не строка.

Для hint `string` сначала пробуется `toString()`, затем `valueOf()`. Для `number` и `default` — наоборот. Если ни один метод не вернул примитив, будет `TypeError`:

```js
const obj = {
  toString() { return 'hello'; },
  valueOf() { return 42; },
};

String(obj); // "hello"
Number(obj); // 42
obj + '';    // "42"
obj + 10;    // 52
```

Пример с точкой на плоскости показывает, зачем это нужно. Сравнивать точки по расстоянию удобно через `valueOf`, а печатать — через `toString`:

```js
const point = {
  x: 3,
  y: 4,
  valueOf() {
    return Math.sqrt(this.x ** 2 + this.y ** 2); // 5
  },
  toString() {
    return `(${this.x}, ${this.y})`;
  },
};

Number(point); // 5
`${point}`;    // "(3, 4)"
point + 10;    // 15
```

Если нужен полный контроль, задают `Symbol.toPrimitive`. Один метод получает hint и возвращает нужный примитив. Он перекрывает `valueOf` и `toString`:

```js
const money = {
  amount: 100,
  [Symbol.toPrimitive](hint) {
    if (hint === 'string') return `$${this.amount}`;
    return this.amount;
  },
};

String(money); // "$100"
money * 2;     // 200
```

## Сравнения и равенство

**`===`** сравнивает тип и значение без преобразований:

```js
5 === '5';          // false
null === undefined; // false
0 === false;        // false
```

**`==`** сначала приводит типы. Отсюда неожиданные результаты:

```js
5 == '5';          // true
0 == false;        // true
'' == false;       // true
[] == false;       // true
```

Практическое правило: используй `===`. Исключение одно: проверка `value == null`, которая ловит и `null`, и `undefined`:

```js
if (value == null) {
  // value === null || value === undefined
}
```

**Сравнения `<`, `>`, `<=`, `>=`** тоже приводят типы, и результат может удивить. Если оба операнда строки, сравнение лексикографическое. Если один — число, строка превращается в число:

```js
'10' < '9';  // true: сравниваются символы, '1' < '9'
'10' < 9;    // false: '10' становится 10
```

**`Object.is`** почти как `===`, но различает два случая:

```js
Object.is(NaN, NaN); // true
Object.is(+0, -0);   // false
NaN === NaN;         // false
+0 === -0;           // true
```

Для проверки именно `NaN` используй `Number.isNaN`. Глобальный `isNaN` сначала приводит аргумент к числу, и поэтому `isNaN('NaN')` даёт `true`.

## Ловушки на собеседованиях

Каждый пример показывает результат через `// →`. Разбор каждого — в соответствующем разделе выше.

```js
[] + {};   // → "[object Object]": [] → '', {} → "[object Object]"
```

```js
{} + [];   // → 0 в начале инструкции: {} это блок кода, остаётся +[] → 0
```

```js
[] + [];   // → '': оба приводятся к пустой строке
[1, 2, 3] + ''; // → '1,2,3': массив превращается в строку через join(',')
```

```js
0.1 + 0.2;       // → 0.30000000000000004
0.1 + 0.2 === 0.3; // → false
```

Дроби в двоичной системе не умеют точно представлять многие десятичные значения. Сравнивают с допуском, который зависит от величины чисел:

```js
function nearlyEqual(a, b, tolerance = 1e-9) {
  return Math.abs(a - b) <= tolerance * Math.max(1, Math.abs(a), Math.abs(b));
}

nearlyEqual(0.1 + 0.2, 0.3); // → true
```

Фиксированный `Number.EPSILON` тут не подходит: для чисел порядка миллиона он меньше шага двоичного представления, и сравнение опять даст `false`.

```js
3 > 2 > 1;      // → false: 3 > 2 даёт true, затем true > 1 — это 1 > 1
```

```js
null == 0;      // → false: null равен только undefined
null >= 0;      // → true: при сравнении null становится 0
```

```js
Number('');     // → 0
Number(' ');    // → 0
parseInt('');   // → NaN
```

```js
Symbol('id') + ''; // → TypeError: символ нельзя неявно привести к строке
String(Symbol('id')); // → 'Symbol(id)'
```

```js
typeof NaN; // → 'number': NaN — специальное числовое значение
```

## Ключевые тезисы для интервью

- Примитивы копируются по значению, объекты — по ссылке; `===` для объектов сравнивает ссылки, а не содержимое.
- Falsy-значений восемь: `false`, `0`, `-0`, `0n`, `''`, `null`, `undefined`, `NaN`; условие с числом `0` в React выводит `0` на экран.
- `Number()` строг и превращает пустую строку в `0`, `parseInt` читает число с начала строки и даёт `NaN` на пустой строке.
- `+` конкатенирует, если хотя бы один операнд — строка, а `-`, `*`, `/` приводят к числу: отсюда `'5' + 1 === '51'` и `'5' - 1 === 4`.
- ToPrimitive: для hint `string` сначала `toString`, для `number` и `default` сначала `valueOf`; `Symbol.toPrimitive` перекрывает оба.
- Используй `===`, кроме проверки `value == null`; `Object.is` различает `+0` и `-0` и считает `NaN` равным `NaN`, а дробные числа сравнивают с допуском.

## Заключение

Типы в JavaScript кажутся хаотичными, пока не видно две закономерности: примитивы и объекты ведут себя по-разному при копировании, а неявное приведение срабатывает там, где оператор ожидает другой тип. Большинство «странных» результатов из собеседований — это применение этих двух правил: `'5' + 1`, `[] == false`, `null >= 0`, `0` в JSX. Приводи типы явно, сравнивай через `===` и держи в голове восемь falsy-значений. Тогда неожиданный вывод перестанет быть сюрпризом.
