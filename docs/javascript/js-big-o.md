# Алгоритмическая сложность и Big O

Поиск по каталогу в интернет-магазине работает мгновенно на тестовых пятидесяти товарах и зависает на двух секундах на пятидесяти тысячах. Ни одного большого алгоритма в коде нет, есть обычный `includes` внутри цикла. Большое O нужно, чтобы замечать такие места до того, как их заметит пользователь. Это не теория для олимпиад: на фронтенде квадратичный код почти всегда появляется в обработке списков, фильтрах и подписках, а собеседующие проверяют, видишь ли ты его в собственном коде.

## Зачем это фронтендеру

Фронтенд редко требует сложных алгоритмов, но постоянно работает со списками: таблицы, фильтры, поиск, выделение дубликатов, объединение данных из двух ответов API. Здесь важно не «изобрести» быструю сортировку, а заметить, что вложенный цикл на данных, которых станет в десять раз больше, будет в сто раз медленнее.

Понимание Big O даёт три вещи: способность оценить решение до запуска, выбор структуры данных под задачу и уверенность в алгоритмической секции собеседования. Именно последнее чаще всего проверяют на вопросах вроде «какая сложность у твоего решения» и «можно ли быстрее».

## Что такое Big O

**Big O** — нотация, которая описывает, как растёт время выполнения (или объём памяти) при увеличении входных данных. Буква `n` обозначает размер входа, например число элементов в массиве.

Big O описывает **худший случай**: сколько операций потребуется в самом невыгодном варианте. Поэтому константы и младшие слагаемые не учитываются. Три операции или триста — это `O(1)`. Формула `2n + 5` даёт `O(n)`, потому что важен рост, а не точное число.

Аналогия поможет запомнить. Ищешь книгу в библиотеке:

| Ситуация | Сложность |
|---|---|
| Знаешь номер полки и идёшь прямо к ней | `O(1)` |
| Проходишь полки подряд, пока не найдёшь | `O(n)` |
| Делишь зал пополам на каждом шаге | `O(log n)` |
| Сравниваешь каждую книгу с каждой | `O(n²)` |

## Основные классы сложности

### O(1): константное время

Одна операция, независимо от размера данных:

```js
const first = arr[0];

const map = new Map();
map.set('key', 'value');
map.get('key');
```

Доступ по индексу, чтение по ключу в `Map`, чтение свойства объекта — всё это `O(1)` в среднем.

### O(log n): логарифмическое время

Каждый шаг отбрасывает часть данных, обычно половину:

```js
function binarySearch(arr, target) {
  let left = 0;
  let right = arr.length - 1;

  while (left <= right) {
    const mid = Math.floor((left + right) / 2);
    if (arr[mid] === target) return mid;
    if (arr[mid] < target) left = mid + 1;
    else right = mid - 1;
  }

  return -1;
}
```

Почему `log n`: сколько раз можно разделить `n` пополам, пока не останется один элемент. Для миллиона элементов это около двадцати шагов. Цена — требование отсортированных данных. Без сортировки отбрасывать половину нельзя, потому что неизвестно, в какой половине искомое.

Цикл, который на каждом шаге удваивает счётчик, тоже даёт `O(log n)`. Например, `for (let i = 1; i < n; i *= 2)` делает `log₂ n` итераций.

### O(n): линейное время

Один проход по данным:

```js
function findMax(arr) {
  let max = arr[0];

  for (let i = 1; i < arr.length; i++) {
    if (arr[i] > max) max = arr[i];
  }

  return max;
}
```

К линейным относятся `find`, `filter`, `map`, `reduce` и любой цикл по массиву. Каждый из них касается каждого элемента хотя бы раз.

### O(n log n): линеарифмическое время

Типичная оценка для эффективной сортировки. `Array.prototype.sort` в современных движках использует вариант TimSort, и на интервью ожидают именно эту оценку. Точный алгоритм спецификация не фиксирует, но `O(n log n)` — стандартный ответ.

### O(n²): квадратичное время

Два вложенных цикла по одним и тем же данным:

```js
function hasDuplicate(arr) {
  for (let i = 0; i < arr.length; i++) {
    for (let j = i + 1; j < arr.length; j++) {
      if (arr[i] === arr[j]) return true;
    }
  }
  return false;
}
```

При `n = 1000` выполняется около полумиллиона сравнений. При `n = 100 000` — пять миллиардов. Почти всегда такой код можно переписать в `O(n)`, и это первое, что проверяют на собеседовании.

### O(2ⁿ): экспоненциальное время

Количество операций удваивается с каждым новым элементом:

```js
function fibonacci(n) {
  if (n <= 1) return n;
  return fibonacci(n - 1) + fibonacci(n - 2);
}
```

Дерево вызовов здесь растёт вдвое на каждом уровне. При `n` около 40 вычисление уже заметно тормозит, а при `n = 60` не закончится за разумное время.

## Пространственная сложность

Big O оценивает и время, и память. **Пространственная сложность** — это объём дополнительной памяти, которую алгоритм выделяет сверх входных данных.

| Подход | Пространственная сложность |
|---|---|
| Изменение массива на месте | `O(1)` |
| Создание нового массива того же размера | `O(n)` |
| Рекурсия глубиной `n` | `O(n)` из-за стека вызовов |

```js
// O(1): разворачиваем массив на месте
function reverseInPlace(arr) {
  let left = 0;
  let right = arr.length - 1;

  while (left < right) {
    [arr[left], arr[right]] = [arr[right], arr[left]];
    left++;
    right--;
  }
}

// O(n): создаём новый массив
function reverseNew(arr) {
  return [...arr].reverse();
}
```

Рекурсия тратит память, даже если в коде нет ни одного массива: каждый незавершённый вызов занимает кадр в стеке. Поэтому глубокая рекурсия по данным — это тоже `O(n)` памяти.

## Скрытый квадрат в JavaScript

Самые опасные места — те, где вложенного цикла нет. Вызов метода внутри цикла стоит столько же, сколько сам метод, и если он линейный, получается квадрат.

### `includes` или `indexOf` внутри цикла

```js
const unique = [];
for (const item of items) {
  if (!unique.includes(item)) unique.push(item); // includes — O(n)
}
```

Это `O(n²)`. Тот же результат через `Set` работает за `O(n)`:

```js
const unique = [...new Set(items)];
```

### `shift` в цикле

`shift` удаляет первый элемент и сдвигает все остальные. Это линейная операция:

```js
while (queue.length > 0) {
  const node = queue.shift(); // O(n) на каждой итерации
  // ...
}
```

Для очереди, которую обходят по порядку, достаточно указателя на голову:

```js
let head = 0;
while (head < queue.length) {
  const node = queue[head++]; // O(1)
  // ...
}
```

### `slice` внутри цикла

`slice()` без аргументов копирует весь массив. Копирование в цикле — тот же квадрат, даже если копия выглядит безобидно:

```js
for (let i = 0; i < n; i++) {
  const copy = values.slice(); // O(n) на каждой итерации
  process(copy);
}
```

### `[...acc, item]` внутри `reduce`

Этот случай связан с функциональным стилем, который часто пишут в React. Каждый шаг создаёт новый массив и копирует в него весь аккумулятор:

```js
const doubled = items.reduce((acc, x) => [...acc, x * 2], []); // O(n²)

const doubledFast = items.map((x) => x * 2); // O(n)
```

Иммутабельность здесь не отменяется, но её выражают через `map` и `filter`, которые сразу создают результат, а не копируют его на каждом шаге.

## Типичные задачи с собеседований

### Задача 1. Two Sum

> Дан массив чисел и число `target`. Найди два индекса, сумма значений по которым равна `target`.

**Плохое решение, `O(n²)`:**

```js
function twoSum(nums, target) {
  for (let i = 0; i < nums.length; i++) {
    for (let j = i + 1; j < nums.length; j++) {
      if (nums[i] + nums[j] === target) return [i, j];
    }
  }
}
```

**Хорошее решение, `O(n)`:**

```js
function twoSum(nums, target) {
  const seen = new Map();

  for (let i = 0; i < nums.length; i++) {
    const complement = target - nums[i];
    if (seen.has(complement)) return [seen.get(complement), i];
    seen.set(nums[i], i);
  }
}
```

Второй цикл заменяем `Map`: для каждого числа проверяем, видели ли мы дополнение до `target`. Проверка за `O(1)`, итог `O(n)`.

### Задача 2. Проверка на дубликаты

```js
function hasDuplicate(arr) {
  return new Set(arr).size !== arr.length;
}
```

Если размер `Set` меньше длины массива, значит, часть элементов совпала. Сложность `O(n)`.

### Задача 3. Частота символов

```js
function charFrequency(str) {
  const freq = {};
  for (const char of str) {
    freq[char] = (freq[char] || 0) + 1;
  }
  return freq;
}
```

Время `O(n)`, память `O(k)`, где `k` — число различных символов.

### Задача 4. Палиндром

```js
function isPalindrome(str) {
  let left = 0;
  let right = str.length - 1;

  while (left < right) {
    if (str[left] !== str[right]) return false;
    left++;
    right--;
  }

  return true;
}
```

Два указателя сходятся к середине. Время `O(n)`, память `O(1)`.

### Задача 5. Пропущенное число

В массиве от `1` до `n` пропущено одно число.

```js
function findMissing(arr, n) {
  const expectedSum = (n * (n + 1)) / 2;
  const actualSum = arr.reduce((sum, num) => sum + num, 0);
  return expectedSum - actualSum;
}
```

Формула суммы арифметической прогрессии заменяет сортировку или `Set`. Время `O(n)`, память `O(1)`.

## Как оптимизировать: паттерны

Большинство улучшений укладываются в четыре приёма.

**1. Вложенный цикл заменить хеш-таблицей.** Для каждого элемента проверяем, есть ли нужное значение в `Set` или `Map`. Пример с Two Sum выше.

**2. Два указателя.** Работает на отсортированных данных: указатели движутся навстречу или в одном направлении и проходят массив один раз. Палиндром и поиск пары с заданной суммой в отсортированном массиве — примеры.

**3. Скользящее окно.** Для подмассивов фиксированной длины не пересчитываем сумму заново, а добавляем новый элемент и вычитаем старый:

```js
let sum = 0;
for (let i = 0; i < k; i++) sum += arr[i];

let max = sum;
for (let i = k; i < arr.length; i++) {
  sum += arr[i] - arr[i - k];
  max = Math.max(max, sum);
}
```

**4. Мемоизация рекурсии.** Кэшируем уже вычисленные значения, и каждое подзадача считается один раз:

```js
const memo = new Map();

function fib(n) {
  if (n <= 1) return n;
  if (memo.has(n)) return memo.get(n);

  const value = fib(n - 1) + fib(n - 2);
  memo.set(n, value);
  return value;
}
```

Сложность падает с `O(2ⁿ)` до `O(n)`.

## Встроенные структуры данных и их сложность

| Операция | Array | Map | Set |
|---|---|---|---|
| Доступ по индексу | `O(1)` | — | — |
| Чтение / запись по ключу | — | `O(1)` в среднем | — |
| Поиск по значению | `O(n)` (`includes`, `indexOf`) | — | `O(1)` в среднем (`has`) |
| Добавление в конец | `O(1)` в среднем (`push`) | `O(1)` в среднем (`set`) | `O(1)` в среднем (`add`) |
| Добавление или удаление в начале | `O(n)` (`unshift`, `shift`) | — | — |
| Удаление по ключу или значению | `O(n)` (`splice`) | `O(1)` в среднем (`delete`) | `O(1)` в среднем (`delete`) |

Главное правило: если нужен частый поиск, бери `Set` или `Map`, а не массив. Если нужна очередь, не используй `shift`, а держи указатель на голову.

## Ключевые тезисы для интервью

- Big O описывает рост числа операций при росте `n` и смотрит на худший случай; константы и младшие слагаемые не учитываются.
- Два вложенных цикла по одному массиву дают `O(n²)`; почти всегда это заменяется `Set` или `Map` и даёт `O(n)`.
- Квадратичность скрывают вызовы: `includes`, `indexOf`, `shift`, `slice` и `[...acc, x]` внутри цикла или `reduce` стоят линейно, и вложенного цикла в коде может не быть.
- Бинарный поиск даёт `O(log n)`, потому что отбрасывает половину данных на каждом шаге, но работает только на отсортированном массиве.
- Доступ по индексу, по ключу `Map` и по свойству объекта в среднем `O(1)`, поиск по значению в массиве — `O(n)`.
- Пространственная сложность оценивается отдельно: рекурсия глубиной `n` тратит `O(n)` памяти на стек даже без массивов.

## Заключение

Big O нужен, чтобы замечать рост до того, как он станет проблемой. Почти все квадратичные места во фронтенде выглядят безобидно: `includes` в фильтре, `shift` в очереди, копия в цикле, `reduce` с распылением массива. Если на каждом вызове метода спрашивать себя, линейный ли он, ты увидишь эти места раньше, чем пользователь увидит зависший интерфейс. А на собеседовании достаточно назвать сложность своего решения и предложить `Set`, `Map` или два указателя, чтобы показать понимание.
