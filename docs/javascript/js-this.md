# Контекст выполнения и `this`

Ты передал метод `user.greet` в `setTimeout`, и через секунду в консоли появилось `Hello, ` вместо имени. Код выглядит правильно: метод на месте, объект на месте, никаких опечаток. Всё дело в том, что `this` определяется не тем, где написана функция, а тем, как её вызвали. В `setTimeout` её вызвали без объекта, и `user` потерялся. Эта статья о том, как читать вызов и предсказывать, чему равен `this`.

## Как определяется `this`

Значение `this` вычисляется в момент вызова, а не в момент объявления функции. Одна и та же функция может видеть разный `this` при разных вызовах:

| Способ вызова | Значение `this` |
| --- | --- |
| Обычный вызов `fn()` | Глобальный объект в нестрогом режиме, `undefined` в strict mode |
| Вызов через точку `obj.fn()` | Объект перед точкой |
| `new Fn()` | Новый создаваемый объект |
| `fn.call(obj)`, `fn.apply(obj)`, `fn.bind(obj)` | Явно переданный `obj` |
| Стрелочная функция | `this` из окружения, где её создали |

Порядок проверки простой: сначала смотрим, не стоит ли функция в `new`, затем не вызвана ли она через `call`, `apply` или `bind`, затем есть ли объект перед точкой. Если ничего из этого нет, `this` берётся по умолчанию.

## Обычный вызов и глобальный контекст

В глобальном коде `this` указывает на глобальный объект. В браузере это `window`, в Node.js в CommonJS-модуле верхний `this` — это `module.exports`, а не `global`:

```js
// браузер, обычный <script>
console.log(this); // window
```

Обычный вызов функции зависит от режима:

```js
function example() {
  console.log(this);
}

example(); // window в нестрогом режиме, undefined в strict mode
```

Модули ES и классы работают в strict mode, поэтому там `this` в обычной функции будет `undefined`. Это одна из причин, почему современный код почти не полагается на `this` без объекта.

## Метод объекта и потеря `this`

Когда функция вызывается через точку, `this` указывает на объект перед точкой:

```js
const user = {
  name: 'Alice',
  greet() {
    console.log(`Hello, ${this.name}`);
  },
};

user.greet(); // Hello, Alice
```

Теперь представь, что тот же метод передали в обработчик или таймер:

```js
const greet = user.greet;
greet(); // вызов без точки
```

Здесь нет объекта перед точкой, поэтому `this` берётся по умолчанию. В браузере это `window`, и `window.name` по умолчанию пустая строка: выведется `Hello, `. В strict mode `this` будет `undefined`, и `this.name` выбросит `TypeError`.

### `setTimeout` и обработчики

С `setTimeout` то же самое. Браузер вызывает переданную функцию сам, без объекта перед точкой:

```js
setTimeout(user.greet, 1000); // Hello, (в браузере)
```

В Node.js `this` внутри колбэка таймера — объект `Timeout`, поэтому вывод будет `Hello, undefined`. Поведение зависит от окружения, но результат одинаково неверный: `user` потерян.

Так же ведут себя обработчики событий. Передача `user.greet` в `addEventListener` теряет `user`: браузер вызывает обработчик, подставляя в `this` элемент, на котором сработало событие.

### Три способа исправить

```js
// 1. Обёртка в стрелочную функцию: вызов идёт через точку
setTimeout(() => user.greet(), 1000); // Hello, Alice

// 2. bind: фиксируем объект заранее
setTimeout(user.greet.bind(user), 1000); // Hello, Alice

// 3. Сохранить ссылку на объект в переменную (старый подход)
const self = this;
setTimeout(function () {
  self.greet();
}, 1000);
```

Первый вариант обычно самый читаемый. `bind` удобен, когда функцию нужно передать дальше без лишней обёртки.

## Конструктор и `new`

При вызове функции с `new` создаётся новый объект, и `this` указывает на него:

```js
function Person(name) {
  this.name = name;
}

const alice = new Person('Alice');
console.log(alice.name); // Alice
```

Если забыть `new`, функция выполнится как обычный вызов. В нестрогом режиме `this.name = name` запишет свойство в глобальный объект:

```js
const bob = Person('Bob');
console.log(bob);  // undefined
console.log(name); // Bob — свойство попало в глобальный объект
```

В strict mode тот же вызов выбросит `TypeError`, потому что `this` равен `undefined`. Классы защищены лучше: вызов класса без `new` всегда даёт `TypeError`.

## `call`, `apply`, `bind`

Эти методы позволяют передать `this` явно.

```js
function greet(greeting) {
  console.log(`${greeting}, ${this.name}`);
}

const user = { name: 'Alice' };

greet.call(user, 'Hello');  // Hello, Alice
greet.apply(user, ['Hi']);  // Hi, Alice
```

`call` принимает аргументы через запятую, `apply` — массивом. Раньше `apply` был нужен, чтобы передать массив в функцию с переменным числом аргументов, но сейчас для этого есть spread: `greet.call(user, ...args)`.

`bind` не вызывает функцию, а возвращает новую с зафиксированным `this`:

```js
const greetUser = greet.bind(user);
greetUser('Hey'); // Hey, Alice

const again = greetUser.bind(someOtherObject);
again('Yo'); // Yo, Alice — повторный bind не меняет this
```

Зафиксированный `this` нельзя переназначить ни `call`, ни `apply`, ни повторным `bind`.

## Стрелочные функции

Стрелочные функции не имеют собственного `this`. Они берут его из окружения, в котором были созданы, и это решение принимается один раз.

Это полезно внутри методов, когда колбэк должен видеть объект метода:

```js
const user = {
  name: 'Alice',
  greetDelayed() {
    setTimeout(() => {
      console.log(`Hello, ${this.name}`); // this из greetDelayed
    }, 1000);
  },
};

user.greetDelayed(); // Hello, Alice
```

Обычная функция внутри `setTimeout` получила бы свой `this`. Стрелочная берёт `this` у `greetDelayed`, а тот вызван через `user`.

Обратная ситуация — стрелочная функция как метод объекта — даёт неожиданный результат:

```js
const obj = {
  value: 42,
  regular() {
    console.log(this.value);
  },
  arrow: () => {
    console.log(this.value);
  },
};

obj.regular(); // 42
obj.arrow();   // undefined
```

У `arrow` нет своего `this`, и внешнее окружение здесь — модуль или глобальный код, а не объект `obj`. Поэтому `this.value` читает свойство глобального объекта, которого нет. Правило простое: стрелочная функция в свойстве объекта не получает сам объект.

## `this` в классах

В методах класса `this` указывает на экземпляр:

```js
class Person {
  constructor(name) {
    this.name = name;
  }

  greet() {
    console.log(`Hello, ${this.name}`);
  }
}

const alice = new Person('Alice');
alice.greet(); // Hello, Alice
```

Но тело класса всегда выполняется в strict mode, поэтому потеря `this` выглядит жёстче:

```js
const greet = alice.greet;
greet(); // TypeError: Cannot read properties of undefined (reading 'name')
```

### Привязка в конструкторе

В классовых компонентах React раньше привязывали методы в конструкторе:

```jsx
class Counter extends React.Component {
  constructor(props) {
    super(props);
    this.state = { count: 0 };
    this.handleClick = this.handleClick.bind(this);
  }

  handleClick() {
    this.setState({ count: this.state.count + 1 });
  }

  render() {
    return <button onClick={this.handleClick}>Click</button>;
  }
}
```

### Стрелочное поле класса

Современный вариант — стрелочная функция как поле класса. Она создаётся для каждого экземпляра и захватывает его `this`:

```jsx
class Counter extends React.Component {
  state = { count: 0 };

  handleClick = () => {
    this.setState({ count: this.state.count + 1 });
  };

  render() {
    return <button onClick={this.handleClick}>Click</button>;
  }
}
```

Это удобно, но метод не лежит в прототипе: каждый экземпляр получает свою копию функции.

## `this` в обработчиках событий React

### Функциональные компоненты

В функциональных компонентах проблемы с `this` нет, потому что методов объекта нет. Важнее замыкание: обработчик видит props того рендера, в котором был создан.

```jsx
function User({ name }) {
  function handleClick() {
    console.log(name); // имя из замыкания, а не this
  }

  return <button onClick={handleClick}>Show name</button>;
}
```

### Классовый компонент

```jsx
class Search extends React.Component {
  constructor(props) {
    super(props);
    this.handleSubmit = this.handleSubmit.bind(this);
  }

  handleSubmit(e) {
    e.preventDefault();
    console.log(this.props.query);
  }

  render() {
    return <form onSubmit={this.handleSubmit}>...</form>;
  }
}
```

Без `bind` React вызовет `handleSubmit` как обычную функцию, и `this.props` упадёт с `TypeError`. Это та же потеря контекста, что и с `setTimeout`, только в обработчике.

## Ключевые тезисы для интервью

- `this` определяется способом вызова, а не местом объявления: одна и та же функция видит разный `this` при разных вызовах.
- Вызов через точку передаёт в `this` объект перед точкой; без точки — глобальный объект или `undefined` в strict mode, и отсюда почти все потери контекста.
- Метод, переданный в `setTimeout` или как колбэк, теряет объект; лечится обёрткой `() => obj.method()` или `bind`.
- `call` и `apply` вызывают функцию с явным `this` и отличаются форматом аргументов, а `bind` возвращает новую функцию с зафиксированным `this`, который нельзя переназначить.
- Стрелочная функция не имеет своего `this` и берёт его из окружения, где её создали: внутри метода она сохраняет объект, но как метод объекта — не годится.
- Конструктор без `new` в нестрогом режиме пишет в глобальный объект, в strict mode падает; класс без `new` всегда выбрасывает `TypeError`.
- React вызывает обработчики без объекта, поэтому методы классовых компонентов нужно привязывать через `bind` или стрелочное поле класса.

## Заключение

`this` кажется сложным, потому что ответ зависит от вызова, а не от текста функции. Полезно задавать один вопрос: что стоит перед точкой в момент вызова? Если ответа нет, `this` будет глобальным или `undefined`. Потеря `this` в колбэках встречается почти везде, и стрелочные функции или `bind` решают её в одну строку. Понимание того, как работают `call`, `apply` и `bind`, позволяет читать чужой код и отлаживать ошибки «`Cannot read properties of undefined`» без догадок.
