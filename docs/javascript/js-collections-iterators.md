# Коллекции, итераторы, генераторы

Представь кэш пользователей, который ты хранишь в обычном объекте. Ключи — идентификаторы, и иногда они приходят числом, иногда строкой. Через неделю выясняется, что `cache[1]` и `cache['1']` — одна и та же запись, а порядок ключей при выводе не совпадает с порядком добавления. Для таких задач в JavaScript есть `Map`, `Set` и их слабые версии. А итераторы — протокол, который позволяет одинаково обходить массивы, строки, коллекции и собственные структуры через `for...of`, spread и деструктуризацию. Эти темы регулярно встречаются на собеседованиях, а в реальном коде сталкиваешься с ними постоянно.

## Object vs Map

Объект удобен, пока ключи — строки. Как только в нём появляются другие ключи, он начинает тихо менять их смысл:

```js
const obj = {};
obj[1] = 'one';      // ключ станет строкой "1"
obj['1'] = 'uno';    // та же запись, значение перезаписано
obj[{}] = 'object';  // ключ станет строкой "[object Object]"
```

Самая коварная ловушка — DOM-элементы. Все они при приведении к строке дают `"[object HTMLDivElement]"`, поэтому объект-словарь, где ключом служит элемент, склеит их все в одну запись. `Map` хранит ключ как ссылку и различает элементы:

```js
const cards = new Map();
cards.set(firstCard, { selected: true });
cards.set(secondCard, { selected: false });
```

Вот сравнение, которое полезно держать в голове:

| Особенность | Object | Map |
|---|---|---|
| Типы ключей | Строки и символы | Любые значения, включая объекты |
| Порядок | Числовые ключи по возрастанию, затем строки по вставке | Строго по вставке |
| Размер | Через `Object.keys(obj).length` | `map.size` |
| Перебор | `for...in` или `Object.keys` с фильтрацией | `for...of`, `forEach` |
| Наследство | Свойства из `Object.prototype` (`toString` и другие) | Ничего лишнего |

## Map

`Map` хранит пары ключ-значение и помнит порядок вставки.

```js
const user = { name: 'Alice' };
const visits = new Map();

visits.set(user, 5);
visits.set('homepage', true);
visits.set(42, 'answer');

console.log(visits.get(user));         // 5
console.log(visits.has('homepage'));   // true
console.log(visits.size);              // 3

visits.delete(42);
visits.clear();
```

Ключ `user` — объект, и `Map` хранит именно ссылку на него. Поэтому ключ можно использовать как «пометку» для любых данных, не добавляя свойств в сам объект.

### Инициализация и перебор

```js
const map = new Map([
  ['name', 'Alice'],
  ['age', 30],
]);

for (const [key, value] of map) {
  console.log(key, value);
}

console.log([...map.keys()]);    // ['name', 'age']
console.log([...map.values()]);  // ['Alice', 30]
```

`map.get` для отсутствующего ключа возвращает `undefined`. Чтобы отличить «ключа нет» от «значение `undefined`», используй `map.has`.

### Когда брать Map вместо объекта

- Ключи — не строки: объекты, DOM-элементы, функции.
- Важен порядок вставки.
- Записи часто добавляются и удаляются, а размер нужно знать быстро.
- Нельзя рисковать конфликтом с унаследованными свойствами, например ключом `constructor`.

## Set

`Set` — коллекция уникальных значений. Повторное добавление ничего не меняет.

```js
const set = new Set([1, 2, 2, 3, 3, 3]);

console.log(set);       // Set { 1, 2, 3 }
console.log(set.size);  // 3

set.add(4);
set.delete(2);
console.log(set.has(4)); // true
```

### Уникализация массива

Самый частый приём: в API пришёл список тегов с повторами, и их нужно показать один раз.

```js
const tags = ['react', 'vue', 'react', 'js', 'vue'];
const unique = [...new Set(tags)];

console.log(unique); // ['react', 'vue', 'js']
```

### Как Set сравнивает значения

`Set` использует SameValueZero: это как `===`, но `NaN` равен `NaN`. Поэтому `new Set([NaN, NaN])` содержит один элемент, а `NaN === NaN` даёт `false`.

Объекты сравниваются по ссылке. Два одинаковых по содержимому объекта — два разных элемента:

```js
const a = { id: 1 };
const b = { id: 1 };

console.log(new Set([a, a, b]).size); // 2
```

Если нужна уникальность по данным, вычисляют ключ из полей и хранят его в `Set` или `Map`. Использовать `JSON.stringify` как ключ можно, но результат зависит от порядка полей, поэтому одинаковые данные с разным порядком ключей дадут разные строки.

## WeakMap и WeakSet

`WeakMap` и `WeakSet` похожи на `Map` и `Set`, но держат **слабые ссылки** на объекты. Сборщик мусора не учитывает такие ссылки: если объект больше никем не используется, он будет удалён вместе с записью.

Представь, что к DOM-узлам ты привязываешь служебные данные. Обычный `Map` держал бы узел в памяти даже после удаления его из страницы. `WeakMap` этого не делает.

### WeakMap

```js
const cache = new WeakMap();

let user = { name: 'Alice' };
cache.set(user, { visits: 5 });

console.log(cache.get(user)); // { visits: 5 }

user = null; // на объект больше нет ссылок
// запись может исчезнуть, когда сборщик мусора решит её удалить
```

У `WeakMap` есть три ограничения, и все они следуют из слабых ссылок:

- ключами могут быть только объекты (и функции);
- перебора нет: нет `size`, `keys`, `values`, `forEach`, `clear`;
- содержимое нельзя ни перечислить, ни проверить целиком.

### WeakSet

`WeakSet` хранит только объекты и помечает их, не удерживая в памяти:

```js
const processed = new WeakSet();

const node = document.getElementById('app');
processed.add(node);

console.log(processed.has(node)); // true
```

Типичные применения: приватные данные объекта, кэши, которые должны очищаться сами, и пометки «этот узел уже обработан».

## Итераторы и `Symbol.iterator`

Зачем вообще нужен протокол итераторов? Представь, что ты пишешь функцию, которая принимает «любую последовательность» и выводит её элементы. Без протокола пришлось бы отдельно обрабатывать массивы, `Set`, строки и `Map`. Протокол решает это одним правилом.

**Итератор** — объект с методом `next()`, который возвращает `{ value, done }`.

**Итерируемый объект** — объект с методом `[Symbol.iterator]`, который возвращает итератор.

Массивы, строки, `Map`, `Set` и `TypedArray` итерируемы по умолчанию:

```js
const arr = [1, 2, 3];
const iterator = arr[Symbol.iterator]();

console.log(iterator.next()); // { value: 1, done: false }
console.log(iterator.next()); // { value: 2, done: false }
console.log(iterator.next()); // { value: 3, done: false }
console.log(iterator.next()); // { value: undefined, done: true }
```

### Собственный итерируемый объект

Диапазон чисел — хороший пример. Объект не хранит массив чисел, а вычисляет их по мере обхода:

```js
const range = {
  from: 1,
  to: 5,

  [Symbol.iterator]() {
    let current = this.from;
    return {
      next: () => {
        if (current <= this.to) {
          return { value: current++, done: false };
        }
        return { value: undefined, done: true };
      },
    };
  },
};

for (const num of range) {
  console.log(num); // 1, 2, 3, 4, 5
}
```

Итератор не обязан быть конечным. Пока потребитель сам решает, сколько значений взять, бесконечная последовательность безопасна:

```js
const fibonacci = {
  [Symbol.iterator]() {
    let a = 0;
    let b = 1;
    return {
      next: () => {
        const value = a;
        [a, b] = [b, a + b];
        return { value, done: false };
      },
    };
  },
};

const [first, second, third] = fibonacci;
console.log(first, second, third); // 0 1 1
```

## `for...of`, spread, деструктуризация

Эти конструкции не знают, что перед ними: массив, `Set` или твой диапазон. Они просто обращаются к `[Symbol.iterator]` и вызывают `next()`, пока `done` не станет `true`.

### `for...of`

```js
for (const char of 'abc') {
  console.log(char); // a, b, c
}

for (const [key, value] of new Map([['x', 1], ['y', 2]])) {
  console.log(key, value);
}
```

`for...of` и `for...in` легко перепутать. `for...of` перебирает **значения** итератора. `for...in` перебирает **строковые ключи**, включая унаследованные перечисляемые свойства, поэтому по массиву он может выдать неожиданные ключи, если кто-то расширил `Array.prototype`.

### Spread

```js
const set = new Set([1, 2, 3]);
const arr = [...set, 4, 5]; // [1, 2, 3, 4, 5]

const map = new Map([['a', 1], ['b', 2]]);
const obj = Object.fromEntries(map); // { a: 1, b: 2 }
```

### Деструктуризация

```js
const [first, second] = new Set([10, 20, 30]);
console.log(first, second); // 10 20

const [[key, value]] = new Map([['name', 'Alice']]);
console.log(key, value); // name Alice
```

Обрати внимание: деструктуризация берёт только столько значений, сколько запрошено. Поэтому деструктуризация бесконечного итератора из примера выше работает.

## Генераторы

Писать итераторы вручную с состоянием в замыканиях неудобно. Генератор, объявленный через `function*`, делает то же самое, но выглядит как обычная функция. Его выполнение можно приостанавливать на `yield` и продолжать при следующем `next()`.

```js
function* counter() {
  let count = 0;
  while (true) {
    yield count++;
  }
}

const gen = counter();
console.log(gen.next().value); // 0
console.log(gen.next().value); // 1
console.log(gen.next().value); // 2
```

Генератор сам реализует оба протокола: он итератор и итерируемый объект. Поэтому `range` из раздела выше переписывается в три строки:

```js
function* range(from, to) {
  for (let i = from; i <= to; i++) {
    yield i;
  }
}

for (const num of range(1, 5)) {
  console.log(num); // 1, 2, 3, 4, 5
}
```

### Ленивость

Значения вычисляются по требованию. Это позволяет работать с последовательностями, которые нельзя положить в массив целиком:

```js
function* powersOfTwo() {
  let n = 1;
  while (true) {
    yield n;
    n *= 2;
  }
}

const [a, b, c, d] = powersOfTwo();
console.log(a, b, c, d); // 1 2 4 8
```

### Двусторонняя связь через next(value)

Значение, переданное в `next(value)`, становится результатом выражения `yield`. Так генератор может получать данные извне:

```js
function* dialog() {
  const name = yield 'Как вас зовут?';
  const age = yield `Привет, ${name}! Сколько вам лет?`;
  yield `${name}, вам ${age} лет.`;
}

const gen = dialog();
console.log(gen.next().value);        // 'Как вас зовут?'
console.log(gen.next('Alice').value); // 'Привет, Alice! Сколько вам лет?'
console.log(gen.next(30).value);      // 'Alice, вам 30 лет.'
```

Этот приём лежит в основе библиотек, которые управляют асинхронными потоками, например `redux-saga` и ранних `co`. В обычном коде `async/await` закрывает большинство таких задач.

## Подводные камни

Несколько ситуаций из практики, где поведение удивляет:

```js
const obj = {};
obj['__proto__'] = 1;
Object.keys(obj).length; // 0: __proto__ — аксессор, примитив не создаёт свойство

const map = new Map([['a', 1]]);
Object.keys(map).length; // 0: элементы Map не являются свойствами объекта
JSON.stringify(map);     // '{}': Map не сериализуется в JSON

new Map().get('missing'); // undefined: проверять наличие лучше через has

new Map().set(-0, 'zero').get(0); // 'zero': SameValueZero считает -0 и 0 одним ключом

new WeakMap().set('key', 1); // TypeError: ключи WeakMap только объекты
```

Для сериализации `Map` переводят в массив пар: `JSON.stringify([...map])` или `JSON.stringify(Object.fromEntries(map))`, если ключи — строки.

Удаление и повторная вставка меняют порядок `Map` и `Set`:

```js
const set = new Set([1, 2, 3]);
set.delete(1);
set.add(1);
console.log([...set].join(',')); // 2,3,1
```

Элемент, который удалили и вставили заново, стал новым, поэтому он в конце.

## Ключевые тезисы для интервью

- Объект приводит ключи к строкам, и `1` с `'1'` сливаются в один ключ; `Map` сравнивает ключи по SameValueZero без приведения типов, поэтому `NaN` равен `NaN`, а `-0` равен `0`.
- `Map` и `Set` идут строго по порядку вставки; повторная вставка удалённого элемента переносит его в конец. Целочисленные ключи обычного объекта идут первыми, и это не порядок добавления.
- `Set` уникализирует по SameValueZero, но объекты сравнивает по ссылке, поэтому дубликаты по содержимому требуют ключа, вычисленного из полей.
- `WeakMap` и `WeakSet` держат слабые ссылки: записи не мешают сборке мусора, но перебрать их нельзя, потому что содержимое зависит от сборщика.
- Итерируемый объект реализует `[Symbol.iterator]`, возвращающий итератор с `next()`; `for...of`, spread и деструктуризация вызывают его сами, а обычный объект без этого метода не итерируется.
- Генератор приостанавливается на `yield`, поэтому значения вычисляются по требованию и подходят для бесконечных последовательностей, а `next(value)` передаёт данные внутрь.

## Заключение

`Map` и `Set` закрывают задачи, с которыми обычный объект и массив справляются плохо: ключи любого типа, уникальность и предсказуемый порядок. Слабые коллекции нужны, когда хранимые данные не должны продлевать жизнь объектам. Протокол итераторов связывает массивы, строки, коллекции и свои структуры в единую модель, а генераторы делают её удобной и ленивой. Если помнить, что обычный объект приводит ключи к строкам, а `WeakMap` ничего не перечисляет, большинство вопросов на собеседовании про коллекции решаются быстро.
