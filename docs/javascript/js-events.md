# Браузерные события: всплытие, погружение, делегирование

Любой интерфейс в браузере строится на событиях: клик, ввод, отправка формы, прокрутка. Казалось бы, достаточно повесить обработчик — но порядок вызова, отмена действий и количество слушателей определяют, будет ли код предсказуемым и быстрым. Разберём модель событий DOM, разницу между отменой всплытия и отменой действия по умолчанию, а также делегирование — приём, без которого не обходится ни один список или таблица.

## Способы подписаться на событие

Источником события может быть любой `EventTarget`: элемент, `document`, `window`, `XMLHttpRequest`, `Worker`. Подписаться на него можно тремя способами, и они не равнозначны.

### HTML-атрибут

```html
<button onclick="save()">Сохранить</button>
```

Код из атрибута выполняется в глобальной области видимости, обработчик всегда один, а логика перемешана с разметкой. Вдобавок CSP без `unsafe-inline` заблокирует такой вызов. В реальном коде этот способ почти не используют — разве что для быстрых прототипов.

### DOM-свойство

```js
const button = document.querySelector('#save');

button.onclick = function (event) {
  console.log(this === button); // true
};

button.onclick = null; // снять обработчик
```

Свойство хранит ровно одну функцию: повторное присваивание затирает предыдущее. Возврат `false` из такого обработчика отменяет действие по умолчанию — наследие времён до стандартизации.

### `addEventListener`

```js
button.addEventListener('click', handleSave);
button.addEventListener('click', handleAnalytics); // не затрёт первый

button.removeEventListener('click', handleSave);
```

Главный способ подписки. Слушатели вызываются в порядке добавления, одна и та же функция с теми же опциями повторно не регистрируется, а третий аргумент управляет фазой и жизненным циклом подписки.

Обычная функция в роли слушателя получает `this === event.currentTarget`, стрелочная — `this` из внешнего окружения.

> Как `this` теряется при передаче метода объекта в обработчик — в статье [Контекст выполнения и `this`](./js-this.md#потеря-this).

Событие можно вызвать и программно:

```js
button.dispatchEvent(
  new CustomEvent('cart:update', { detail: { count: 2 }, bubbles: true }),
);
```

Такое событие проходит те же фазы, но `event.isTrusted === false` — браузер отличает его от настоящего действия пользователя.

> Базовый синтаксис `addEventListener`, типы событий и свойства объекта события разобраны в статье [Основы JavaScript](./fundamentals.md#события).

## Фазы распространения события

Когда происходит клик по кнопке, событие не появляется сразу на ней — оно проходит путь по дереву DOM в три этапа:

1. **Погружение (capture)** — от `window` вниз через `document` и всех предков к родителю цели.
2. **Цель (target)** — обработчики на самом элементе.
3. **Всплытие (bubble)** — от цели вверх по предкам обратно до `window`.

```html
<div id="outer">
  <div id="inner">
    <button id="button">Click</button>
  </div>
</div>
```

```js
const outer = document.querySelector('#outer');
const inner = document.querySelector('#inner');
const button = document.querySelector('#button');

outer.addEventListener('click', () => console.log('outer: погружение'), true);
inner.addEventListener('click', () => console.log('inner: погружение'), true);
button.addEventListener('click', () => console.log('button: цель'));
inner.addEventListener('click', () => console.log('inner: всплытие'));
outer.addEventListener('click', () => console.log('outer: всплытие'));
```

При клике по кнопке консоль покажет строго этот порядок:

```
outer: погружение
inner: погружение
button: цель
inner: всплытие
outer: всплытие
```

Несколько нюансов, которые любят проверять на собеседовании:

- Третий аргумент `true` (или `{ capture: true }`) включает слушателя на фазе погружения. Без него он сработает на всплытии.
- На самой цели, по спецификации DOM, capture- и bubble-слушатели выполняются **в порядке регистрации** — флаг `capture` здесь приоритета не даёт. На предках приоритет сохраняется.
- `event.eventPhase` показывает текущую фазу: `1` — погружение, `2` — цель, `3` — всплытие.
- Термины «погружение», «захват» и «capture» — об одном и том же.

## `target` и `currentTarget`

Эти два свойства постоянно путают, хотя разница принципиальна:

| Свойство | Что означает |
| --- | --- |
| `event.target` | Элемент, на котором событие произошло. Не меняется по пути |
| `event.currentTarget` | Элемент, на котором сейчас выполняется обработчик. Совпадает с `this` |
| `event.relatedTarget` | Связанный элемент: откуда пришли или куда ушли (`mouseover`/`mouseout`, `focusin`/`focusout`) |
| `event.composedPath()` | Полный путь события от `window` до цели, включая теневые корни |

```html
<ul id="list">
  <li><span>Пункт 1</span></li>
</ul>
```

```js
const list = document.querySelector('#list');

list.addEventListener('click', (event) => {
  console.log(event.target);        // <span> — реальная цель
  console.log(event.currentTarget); // <ul> — где висит обработчик
});
```

В теневом DOM есть ещё один слой: при выходе события за границу shadow root свойство `target` подменяется на хост-элемент (retargeting), а настоящую цель видно только через `composedPath()` во время обработки. События с `composed: false` за границу теневого дерева вообще не выходят.

После завершения диспетчеризации `event.currentTarget` становится `null`, поэтому если ссылка нужна в асинхронном коде — сохраните её заранее.

## Отмена всплытия

`stopPropagation()` останавливает дальнейшее распространение события: обработчики на предках уже не сработают.

```js
button.addEventListener('click', (event) => {
  event.stopPropagation();
  console.log('только кнопка');
});
```

Важные детали:

- **Другие слушатели того же элемента всё равно выполнятся.** Метод останавливает переход к следующему узлу, а не текущую фазу.
- **`stopImmediatePropagation()`** останавливает и оставшиеся слушатели текущего элемента, и дальнейшее распространение.
- Вызов в capture-слушателе на предке не пустит событие даже до цели.
- Устаревший синоним — `event.cancelBubble = true`.

```js
button.addEventListener('click', (event) => {
  event.stopImmediatePropagation();
  console.log('первый');
});

button.addEventListener('click', () => {
  console.log('второй'); // не выполнится
});
```

Практическое правило: глушить всплытие стоит только при реальной необходимости. `stopPropagation()` ломает делегирование, аналитику и обработчики фреймворка, поэтому чаще достаточно проверить, тот ли это элемент, и просто выйти из обработчика.

## Отмена действия по умолчанию

Всплытие и поведение браузера — независимые вещи. `preventDefault()` отменяет то, что браузер сделал бы сам: переход по ссылке, отправку формы, переключение чекбокса, контекстное меню.

```js
form.addEventListener('submit', (event) => {
  event.preventDefault(); // страница не перезагрузится
  submitWithFetch(new FormData(form));
});
```

Ограничения, о которых спрашивают:

- Метод работает только для отменяемых событий — проверка `event.cancelable`.
- Вызывать его нужно во время диспетчеризации. В `setTimeout` внутри обработчика уже поздно: действие по умолчанию к тому моменту выполнено.
- В `passive`-слушателе `preventDefault()` игнорируется: браузер заранее считает, что событие не будет блокирующим.
- `return false` отменяет действие только в обработчике, назначенном через DOM-свойство (`onclick = ...`), но не через `addEventListener`.
- `preventDefault()` не останавливает всплытие.

Сводная таблица различий:

| Метод | Что делает | Что не делает |
| --- | --- | --- |
| `stopPropagation()` | Останавливает переход события к следующим узлам | Не отменяет действие браузера и не снимает другие слушатели текущего узла |
| `stopImmediatePropagation()` | Останавливает и оставшиеся слушатели узла, и распространение | Не отменяет действие браузера |
| `preventDefault()` | Отменяет действие по умолчанию | Не влияет на всплытие |

## Делегирование событий

Идея простая: вместо слушателя на каждом элементе — один на общем предке. Событие всё равно всплывёт до него, а конкретный элемент можно вычислить по `event.target`.

Плохой вариант — обработчик на каждом элементе:

```js
document.querySelectorAll('#list li').forEach((item) => {
  item.addEventListener('click', () => console.log(item.textContent));
});
```

При добавлении нового `<li>` ему понадобится отдельная подписка, а при удалении — снятие. Делегирование решает обе проблемы:

```html
<ul id="list">
  <li data-id="1"><span>Пункт 1</span></li>
  <li data-id="2"><span>Пункт 2</span></li>
</ul>
```

```js
const list = document.querySelector('#list');

list.addEventListener('click', (event) => {
  const item = event.target.closest('li[data-id]');

  if (!item || !list.contains(item)) return;

  console.log('Выбран пункт', item.dataset.id);
});

// Новый элемент сразу работает — слушатель уже на контейнере
list.insertAdjacentHTML('beforeend', '<li data-id="3"><span>Пункт 3</span></li>');
```

Почему именно `closest`, а не `event.target.tagName === 'LI'`: цель клика — обычно вложенный `<span>`, `<svg>` или текст, а `closest` поднимается от реальной цели до ближайшего подходящего предка. Проверка `list.contains(item)` отсекает случай, когда найденный `<li>` принадлежит другому, вложенному списку.

### Что даёт делегирование

- Один слушатель вместо сотен — меньше памяти и подписок.
- Динамически добавленные элементы работают без повторной настройки.
- Логика собрана в одном месте, снимать слушатель нужно тоже один.
- Обновление списка не требует обхода элементов и переподписки.

### Ограничения

- Нужна дополнительная проверка цели на каждое событие — но обычно это дешевле, чем сотни слушателей.
- Событие должно всплывать. Для `focus`, `blur`, `mouseenter`, `mouseleave` и `scroll` на элементе приём не сработает без замены события или capture-слушателя.
- Внутренние обработчики, вызывающие `stopPropagation()`, обрывают путь до контейнера — делегирование перестаёт видеть такие клики.
- Нельзя бездумно передавать `event.target` в асинхронный код: к моменту ответа элемент может быть уже удалён.

Тот же принцип лежит в основе фреймворков: React навешивает один делегированный слушатель на корневой контейнер приложения.

> Как это устроено в React и чем отличается от нативных событий — в статье [Синтетические события](../react/synthetic-events.md#как-работает-система-событий-react).

## Опции слушателя и очистка

Третий аргумент `addEventListener` — либо булево `capture`, либо объект:

| Опция | Смысл |
| --- | --- |
| `capture` | Слушать на фазе погружения вместо всплытия |
| `once` | Снять слушатель автоматически после первого срабатывания |
| `passive` | Пообещать не вызывать `preventDefault()` — браузер не ждёт обработчик перед скроллом |
| `signal` | Снимать слушатель через `AbortController` |

```js
const controller = new AbortController();

window.addEventListener('resize', onResize, {
  passive: true,
  signal: controller.signal,
});

document.addEventListener('keydown', onEscape, { once: true });

// Снимает все слушатели, подписанные на этот сигнал
controller.abort();
```

`passive: true` особенно важен для `touchstart`, `touchmove` и `wheel`: иначе браузер не может начать прокрутку, пока не выполнится обработчик, и страница «дёргается».

Снятие через `removeEventListener` требует **той же ссылки на функцию и того же значения `capture`**:

```js
element.addEventListener('click', handleClick, true);

element.removeEventListener('click', handleClick);      // не сработает
element.removeEventListener('click', handleClick, true); // сработает
```

Анонимную стрелку снять нельзя — ссылки на неё нет. Поэтому обработчик выносят в именованную функцию или используют `AbortController`.

> Почему забытые слушатели удерживают DOM-узлы в памяти — в статье [Память и производительность](./js-memory.md#типичные-утечки-памяти).

## События, которые не всплывают

Не все события проходят полный путь. Часть из них срабатывает только на цели:

| Событие | Всплывает | Альтернатива |
| --- | --- | --- |
| `focus` / `blur` | Нет | `focusin` / `focusout` |
| `mouseenter` / `mouseleave` | Нет | `mouseover` / `mouseout` |
| `pointerenter` / `pointerleave` | Нет | `pointerover` / `pointerout` |
| `load` / `error` (ресурсы) | Нет | Слушатель на самом элементе или capture на `document`/`window` |
| `scroll` (на элементе) | Нет | Слушатель на элементе; прокрутку страницы — на `window` |
| `play`, `pause`, `ended` | Нет | Слушатель на медиаэлементе |
| `click`, `input`, `change`, `submit`, `keydown` | Да | Делегирование работает |

Два практических следствия:

- Невсплывающее событие всё равно проходит фазу погружения, поэтому его можно поймать capture-слушателем на предке: `document.addEventListener('focus', handler, true)`. Но `focusin` обычно читается проще.
- Своё событие по умолчанию **не всплывает**: `new Event('update')` и `new CustomEvent('update')` имеют `bubbles: false`. Для делегирования нужно явно указать `{ bubbles: true }`.

## Ключевые тезисы для интервью

- Событие проходит три фазы: погружение от `window` к родителю цели, фаза цели и всплытие обратно до `window`; на предках capture-слушатели срабатывают раньше bubble, а на самой цели — в порядке регистрации.
- `addEventListener` — основной способ подписки: несколько слушателей на одно событие, управление фазой и опции `once`, `passive`, `signal`; `onclick` перезаписывается, HTML-атрибут смешивает разметку и логику и блокируется строгим CSP.
- `target` — неизменная цель события, `currentTarget` — узел текущего обработчика (он же `this`); на этом расхождении и строится делегирование.
- `stopPropagation` останавливает переход к следующим узлам, но не снимает другие слушатели текущего (для этого нужен `stopImmediatePropagation`) и не отменяет действие браузера — `preventDefault` работает отдельно, только с отменяемыми событиями во время диспетчеризации и не в `passive`-слушателе.
- Делегирование — один слушатель на общем предке плюс поиск цели через `closest`: меньше подписок, автоматическая поддержка динамических элементов, но обязательны фильтр цели и всплывающее событие.
- Невсплывающие события (`focus`, `blur`, `mouseenter`, `mouseleave`, `scroll` на элементе) делегировать напрямую нельзя — помогают `focusin`/`focusout`, `mouseover`/`mouseout` или capture-слушатель.
- `removeEventListener` требует ту же ссылку и тот же флаг `capture`; `AbortController.signal` снимает пачку слушателей разом, `once` делает это автоматически после первого вызова, а `passive` не даёт обработчику блокировать скролл.

## Заключение

Модель событий DOM держится на трёх фазах и двух независимых механизмах отмены: `stopPropagation` управляет распространением, `preventDefault` — поведением браузера. Понимание `target` и `currentTarget` превращает делегирование из трюка в осознанный инструмент: один слушатель на контейнере заменяет сотни подписок и продолжает работать для новых элементов. Ограничения тоже важно помнить — невсплывающие события, `stopPropagation` внутри вложенных обработчиков и требования к ссылке при снятии слушателя. На практике сначала выбирайте событие и фазу, затем решайте, нужен ли `passive` или `once`, и только после этого добавляйте отмены — так код остаётся предсказуемым.
