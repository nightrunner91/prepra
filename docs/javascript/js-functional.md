# Функции и массивы в JavaScript

Представь корзину интернет-магазина. Пользователь добавляет товар, а счётчик в шапке упрямо показывает старое число. Данные в состоянии при этом уже обновились: ты сам видишь их в отладчике. Виноват обычно `push` там, где нужен новый массив. Эта статья про такие мелочи, из-за которых код работает «почти правильно». На собеседованиях их проверяют вопросами вроде «что вернёт `map(parseInt)`» или «изменит ли `sort` исходный массив», и правильный ответ там почти всегда про поведение, а не про названия методов.

## Чистые функции

Возьми функцию `addItem`, которая добавляет товар в корзину. Выглядит безобидно, пока не окажется, что она молча меняет объект, который ей передали:

```js
function addItem(cart, item) {
  cart.items.push(item); // меняет чужой объект
  return cart;
}
```

Вызывающий код не ждёт, что его корзина изменится, а она меняется. Через неделю кто-то вызовет `addItem` дважды на одном объекте, и результат будет зависеть от того, что было раньше. Это и есть побочный эффект: функция делает что-то помимо того, что возвращает.

**Чистая функция** не делает ничего лишнего: на одинаковые аргументы отвечает одинаково и не трогает внешний мир. Вот её версия:

```js
function addItem(cart, item) {
  return { ...cart, items: [...cart.items, item] };
}
```

Исходный `cart` остался нетронутым, а новый объект содержит добавленный товар. Такую функцию легко тестировать: передали вход, проверили выход, никаких моков. Её можно кэшировать, потому что результат зависит только от аргументов. И порядок вызовов ей не важен.

Что считается побочным эффектом, стоит запомнить заранее:

- запись в DOM, `console.log`, сетевой запрос;
- чтение `Date.now()` и `Math.random()`, потому что результат меняется от вызова к вызову;
- чтение и запись внешних переменных, например `let tax` вне функции;
- мутация аргументов.

```js
let tax = 0.2;

function calculatePrice(price) {
  return price * (1 + tax); // зависит от внешней переменной
}
```

Полностью без эффектов приложение не обойдётся: что-то же должно рисовать интерфейс и ходить на сервер. Рабочий подход — разделить код на два слоя. Чистые функции считают данные, а тонкий слой на краю приложения отрисовывает результат или отправляет запрос.

## Иммутабельность

Иммутабельность — это договорённость не менять данные на месте. Вместо правки объекта ты создаёшь новый на основе старого.

```js
const numbers = [1, 2, 3];

numbers.push(4);            // меняет numbers
const nextNumbers = [...numbers, 4]; // numbers не тронут
```

Зачем вообще стараться? Причин три, и каждая встречается в реальной работе.

Первая — React. Он решает, нужна ли перерисовка, сравнивая состояние по ссылке. Если объект мутировать, ссылка остаётся прежней, React считает, что ничего не изменилось, и экран не обновляется. Именно так рождаются баги с «данные есть, а интерфейс старый». `React.memo` и массив зависимостей `useEffect` работают на тех же сравнениях.

Вторая — безопасность при передаче данных. Если объект ушёл в другой модуль, колбэк или асинхронную функцию, никто не знает, кто и когда его поменял. Новый объект на каждое изменение этот вопрос снимает.

Третья — удобство. Каждое состояние становится отдельным снимком, поэтому отмена действия (undo) или разбор, что произошло, делаются без лишней магии.

```js
const user = { name: 'Alice', age: 25 };

user.age = 26;                        // мутация: ссылка та же, React не заметит
const updatedUser = { ...user, age: 26 }; // новая ссылка: изменение видно
```

### Ловушка: spread копирует только верхний уровень

Тут легко обмануться. Выглядит как копия, но вложенный объект общий:

```js
const state = { user: { name: 'Alice' }, theme: 'dark' };

const copy = { ...state };
copy.user.name = 'Bob'; // state.user.name тоже стал 'Bob'
```

Правило простое: копируй каждый уровень, который меняется.

```js
const next = { ...state, user: { ...state.user, name: 'Bob' } };
```

Для глубоких структур бывают `structuredClone` (годится для данных без функций), Immer и Immutable.js. Но обычно хватает spread, `map`, `filter` и `slice`.

## Методы массивов

Почти все методы принимают колбэк, и сигнатура у него одна: `(элемент, индекс, массив)`. Запомни это: половина ловушек из следующего раздела как раз отсюда.

### Что меняет массив, а что нет

Самое болезненное незнание — какие методы трогают исходный массив. Они выглядят одинаково, а поведение разное.

| Задача | Мутирующий метод | Безопасный вариант |
|---|---|---|
| Добавить в конец | `push` | `[...arr, item]` или `arr.concat(item)` |
| Удалить по индексу | `splice` | `arr.filter((_, i) => i !== index)` |
| Заменить элемент | `arr[i] = x` | `arr.map((v, i) => (i === index ? x : v))` |
| Отсортировать | `sort`, `reverse` | `[...arr].sort(compare)` или `arr.toSorted(compare)` |
| Взять кусок | — `slice` не мутирует | `arr.slice(start, end)` |

`toSorted`, `toReversed`, `toSpliced` и `with` появились в ES2023 и работают в современных браузерах и Node.js 20+. В старом коде их может не быть, тогда используй копию через spread.

### `map`: каждый элемент превращается в новый

`map` проходит по массиву и возвращает новый массив той же длины. Исходный не меняется, и это как раз то, что нужно для списка на экране:

```js
const users = [{ name: 'Alice' }, { name: 'Bob' }];
const names = users.map((user) => user.name);

console.log(names); // ['Alice', 'Bob']
console.log(users); // без изменений
```

### `forEach`: вызвали ради эффекта

`forEach` тоже проходит по элементам, но возвращает `undefined`. Его место — логирование, запись в DOM, добавление в уже существующую структуру. Если результат нужен, а ты пишешь `forEach` и складываешь всё в переменную снаружи, это сигнал взять `map`.

```js
const result = [1, 2, 3].forEach((x) => x * 2);
console.log(result); // undefined
```

### `filter`: оставляем нужное

`filter` возвращает новый массив из тех элементов, для которых колбэк вернул истину. Длина может уменьшиться, но не увеличиться.

```js
const orders = [{ total: 500 }, { total: 1200 }, { total: 80 }];
const large = orders.filter((order) => order.total >= 1000);

console.log(large); // [{ total: 1200 }]
```

### `reduce`: свернуть всё в одно значение

`reduce` — самый мощный и самый коварный метод. Аккумулятор получает результат предыдущего шага, а текущий элемент — очередное значение массива. Так считают сумму корзины:

```js
const cart = [
  { price: 300, qty: 2 },
  { price: 150, qty: 1 },
];

const total = cart.reduce((sum, item) => sum + item.price * item.qty, 0);
console.log(total); // 750
```

Обрати внимание на `0` вторым аргументом. Без него первый элемент станет аккумулятором, и на пустой корзине метод упадёт. Об этом ниже, в ловушках.

`reduce` умеет группировать. Вот задачи, разложенные по статусам:

```js
const tasks = [
  { title: 'Написать тесты', status: 'done' },
  { title: 'Ревью', status: 'todo' },
  { title: 'Деплой', status: 'done' },
];

const byStatus = tasks.reduce((acc, task) => {
  acc[task.status] ??= [];
  acc[task.status].push(task);
  return acc;
}, {});

console.log(byStatus.done.length); // 2
```

Здесь аккумулятор мутируется, и это нормально: объект создал сам `reduce` и никому его не отдавал. Если хочется строгой иммутабельности, пишут `{ ...acc, [key]: [...(acc[key] ?? []), task] }`. Но на длинных массивах такое копирование на каждом шаге становится заметно медленным. Для группировки в ES2024 есть `Object.groupBy`.

Всё, что делают `map` и `filter`, можно записать через `reduce`. Но читать такой код тяжело, и коллега тоже будет тратить время. Бери `reduce`, когда нужна именно свёртка: сумма, объект, группировка. Для преобразования и отбора есть `map` и `filter`.

### `find`, `findIndex`, `some`, `every`

```js
const users = [
  { name: 'Alice', admin: true },
  { name: 'Bob', admin: false },
];

users.find((u) => u.admin);      // { name: 'Alice', admin: true }, объект
users.findIndex((u) => u.admin); // 0
users.some((u) => u.admin);      // true
users.every((u) => u.admin);     // false
```

`find` возвращает сам элемент, а не массив, и `undefined`, если никто не подошёл. `some` и `every` всегда дают `true` или `false`, и на пустом массиве они ведут себя противоположно. `some` даёт `false`: ни один элемент не подошёл, потому что элементов нет. `every` даёт `true`: нарушителей нет. Звучит парадоксально, но логично: это следствие того, что они проверяют отсутствие исключений.

### `sort`: сортирует на месте и без спроса

`sort` меняет исходный массив и возвращает ссылку на него же. Без компаратора он сравнивает элементы как строки, и результат удивляет:

```js
[10, 1, 2].sort();                // [1, 10, 2], потому что '10' раньше '2'
[10, 1, 2].sort((a, b) => a - b); // [1, 2, 10]
```

Компаратор возвращает отрицательное число, если `a` должен идти раньше `b`, положительное, если позже, и ноль при равенстве. Для строк с учётом языка используй `localeCompare`: `names.sort((a, b) => a.localeCompare(b, 'ru'))`. Сортировка стабильна с ES2019: равные элементы сохраняют прежний порядок.

### `flat`, `flatMap`, `Array.from`

```js
[1, [2, [3]]].flat();         // [1, 2, [3]], только один уровень
[1, [2, [3]]].flat(Infinity); // [1, 2, 3]

['a b', 'c'].flatMap((s) => s.split(' ')); // ['a', 'b', 'c']

Array.from({ length: 3 }, (_, i) => i * 10); // [0, 10, 20]
```

`flat()` по умолчанию разворачивает один уровень вложенности, а не все. `flatMap` — это `map` с последующим разворачиванием на один уровень, и он удобен, когда каждый элемент даёт несколько значений. `Array.from` создаёт массив из array-like объекта, например `{ length: 3 }`, и принимает маппер вторым аргументом.

Вложенность произвольной глубины обычно разворачивают рекурсией: проверяют каждый элемент через `Array.isArray` и либо добавляют его, либо разворачивают рекурсивно. Этот паттерн есть в практике, задача `flatten`.

### `includes` и `indexOf`

```js
[NaN].includes(NaN); // true
[NaN].indexOf(NaN);  // -1
```

`includes` находит `NaN`, потому что сравнивает значения по SameValueZero. `indexOf` использует строгое равенство, а `NaN !== NaN`, поэтому он `NaN` не находит никогда.

### Сводная таблица

| Метод | Что возвращает | Меняет исходный | Когда брать |
|---|---|---|---|
| `map` | Новый массив той же длины | Нет | Преобразовать каждый элемент |
| `filter` | Новый массив не длиннее исходного | Нет | Оставить нужные элементы |
| `reduce` | Одно значение | Нет | Свернуть в сумму, объект, группировку |
| `forEach` | `undefined` | Нет | Побочный эффект |
| `find` | Элемент или `undefined` | Нет | Найти первый подходящий |
| `some` / `every` | `boolean` | Нет | Есть ли хоть один / все ли |
| `sort` | Тот же массив | Да | Сортировка на месте |
| `slice` | Новый массив | Нет | Копия фрагмента |
| `splice` | Удалённые элементы | Да | Удаление и вставка на месте |

## Ловушки на собеседовании

Ниже девять ситуаций, где код выглядит правильно, а выводит другое. Результат указан после `// →`. Если какая-то кажется неочевидной, загляни в соответствующий раздел выше: ответ там.

```js
[1, 2, 3].forEach((x) => x * 2);  // → undefined
[1, 2, 3].map((x) => x * 2);      // → [2, 4, 6]
```

```js
['1', '2', '3'].map(parseInt);               // → [1, NaN, NaN]
['1', '2', '3'].map((s) => parseInt(s, 10)); // → [1, 2, 3]
```

Почему так: `parseInt` получает `(строка, индекс)`, и индекс становится основанием системы счисления. `parseInt('2', 1)` и `parseInt('3', 2)` дают `NaN`.

```js
[10, 1, 2].sort(); // → [1, 10, 2]
```

```js
const values = [3, 1, 2];
const sorted = values.sort();
sorted === values; // → true: это один и тот же массив
```

```js
[].reduce((a, b) => a + b);    // → TypeError: Reduce of empty array with no initial value
[].reduce((a, b) => a + b, 0); // → 0
```

```js
const a = [1, 2, 3];
a.slice(0, 2);  // → [1, 2], a не изменился
a.splice(0, 2); // → [1, 2], а теперь a — это [3]
```

```js
[NaN].includes(NaN); // → true
[NaN].indexOf(NaN);  // → -1
```

```js
[1, [2, [3]]].flat(); // → [1, 2, [3]]: развернулся только один уровень
```

```js
[1, 2].forEach(async (x) => {
  await null;
  console.log(x);
});
console.log('done');
// → done, 1, 2: forEach не ждёт async-колбэки
```

Если нужно дождаться каждого шага по очереди, используй `for...of` внутри `async`-функции. Если шаги можно выполнить параллельно, используй `await Promise.all(arr.map(async (x) => ...))`.

## Каррирование и композиция

Когда у тебя есть одна общая функция, а нужны десятки её специализированных версий, писать каждую вручную скучно. **Каррирование** решает это: функция от нескольких аргументов превращается в цепочку функций от одного.

```js
const multiply = (a) => (b) => a * b;

const double = multiply(2);
const triple = multiply(3);

console.log(double(7)); // 14
console.log(triple(7)); // 21
```

Похожий приём — **частичное применение**: часть аргументов фиксируется заранее.

```js
function greet(greeting, name) {
  return `${greeting}, ${name}!`;
}

const sayHello = greet.bind(null, 'Hello');
console.log(sayHello('Alice')); // Hello, Alice!
```

**Композиция** — это конвейер: результат одной функции передаётся в следующую. Представь обработку ввода в поиске: обрезать пробелы, привести к верхнему регистру, добавить восклицательный знак. Можно вложить вызовы друг в друга, но читать их придётся изнутри наружу:

```js
const trim = (s) => s.trim();
const toUpper = (s) => s.toUpperCase();
const exclaim = (s) => `${s}!`;

const shout = (s) => exclaim(toUpper(trim(s)));
console.log(shout('  hello  ')); // HELLO!
```

Проще записать конвейер явно. Вот две универсальные версии:

```js
const compose = (...fns) => (x) => fns.reduceRight((acc, fn) => fn(acc), x);
const pipe = (...fns) => (x) => fns.reduce((acc, fn) => fn(acc), x);

const shoutRight = compose(exclaim, toUpper, trim); // читаем справа налево
const shoutLeft = pipe(trim, toUpper, exclaim);     // читаем слева направо

console.log(shoutRight('  hello  ')); // HELLO!
console.log(shoutLeft('  hello  '));  // HELLO!
```

`compose(f, g)` и `pipe(g, f)` дают одно и то же. Разница только в том, как читается код. `pipe` совпадает с порядком выполнения, поэтому в прикладном коде его используют чаще.

## debounce и throttle

Представь поле поиска: пользователь печатает «react», и на каждую букву уходит запрос. Пять запросов вместо одного, и ответы приходят не по порядку. Или обработчик `scroll`, который срабатывает десятки раз за секунду. Обе ситуации решают приёмы, которые ограничивают частоту вызова.

### debounce: ждём, пока человек закончит

**Debounce** откладывает вызов до паузы. Каждое новое событие сбрасывает таймер, и функция срабатывает только тогда, когда события прекратились.

```js
function debounce(fn, delay) {
  let timerId;

  return function (...args) {
    clearTimeout(timerId);
    timerId = setTimeout(() => fn.apply(this, args), delay);
  };
}

const handleInput = debounce((value) => {
  console.log('Search:', value);
}, 300);

// handleInput('r');
// handleInput('re');
// handleInput('react'); // сработает только этот, через 300 мс после последней буквы
```

Это то, что нужно для поиска: важен итоговый запрос, промежуточные нам не нужны.

### throttle: не чаще, чем раз в интервал

**Throttle** пропускает вызовы не чаще заданного интервала. Для scroll это то, что нужно: тебе нужны обновления во время скролла, но не сорок штук в секунду.

```js
function throttle(fn, interval) {
  let lastTime = 0;

  return function (...args) {
    const now = Date.now();

    if (now - lastTime >= interval) {
      lastTime = now;
      fn.apply(this, args);
    }
  };
}

const handleScroll = throttle(() => {
  console.log('Scroll position:', window.scrollY);
}, 200);

window.addEventListener('scroll', handleScroll);
```

У этой версии есть слабость, о которой полезно знать. Она выполняет первый вызов в интервале и отбрасывает остальные, поэтому последнее событие серии может потеряться. Если итоговое состояние важно, добавляют trailing-вызов через `setTimeout`. В lodash для этого есть опции `leading` и `trailing`.

### Что выбрать

| Приём | Когда срабатывает | Пример |
|---|---|---|
| `debounce` | Через паузу после последнего события | Поиск по вводу |
| `throttle` | Регулярно, не чаще интервала | Scroll, resize, координаты мыши |

Простой вопрос, который помогает выбрать: нужен ли промежуточный результат? Нужен — `throttle`. Нужен только финальный — `debounce`.

## Ключевые тезисы для интервью

- Чистая функция для одних и тех же аргументов возвращает одно и то же и не имеет побочных эффектов; эффекты выносят на края приложения.
- React сравнивает состояние по ссылке, поэтому обновление делают новым объектом или массивом; spread копирует только верхний уровень.
- `push`, `splice`, `sort`, `reverse` меняют исходный массив; безопасные варианты — `slice`, spread, `map`, `filter`, а также `toSorted` и `toReversed`.
- Колбэк методов массива получает `(элемент, индекс, массив)`, поэтому `map(parseInt)` даёт `[1, NaN, NaN]`: передавай явную стрелку, если сигнатура не совпадает.
- `map`, `filter` и `reduce` возвращают новое значение, `forEach` возвращает `undefined`; `reduce` без начального значения падает на пустом массиве, поэтому его стоит передавать всегда.
- `forEach` не ждёт промисы из колбэков: для последовательного ожидания берут `for...of` с `await`, для параллельного — `Promise.all(arr.map(...))`.
- `debounce` выполняет функцию после паузы (поиск по вводу), `throttle` — не чаще интервала (scroll и resize).

## Заключение

Функциональный стиль в JavaScript держится на трёх вещах: функции, которые не трогают внешний мир, обновления без мутаций и точное знание того, что делает каждый метод массива. Последнее проверяют на собеседованиях чаще всего: что меняет массив, что получает колбэк, что происходит с пустым массивом. Каррирование и композиция помогают собирать логику из маленьких кусочков, а `debounce` и `throttle` спасают сервер и интерфейс от лавины событий. Переписывать весь код в функциональном стиле не нужно, но эти привычки стоит иметь всегда под рукой.
