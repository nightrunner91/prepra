# Roadmap: React Learn — от markdown к интерактивной учебной платформе

Этот документ описывает план трансформации проекта из набора `.md` файлов в полноценный статический сайт с интерактивными элементами, трекером прогресса и инструментами для эффективного обучения.

---

## Текущее состояние

- **Контент:** ~100+ статей в `/docs`, разбитых на 15 разделов
- **Структура:** Каждая статья содержит теорию, примеры кода и чеклист вопросов
- **Навигация:** `README.md` с чеклистами и ссылками на статьи
- **Методология:** Active Recall, Spaced Repetition, Feynman Technique

**Проблемы текущего состояния:**
- Нет единой навигации между статьями
- Прогресс не сохраняется (нужно вручную отмечать в markdown)
- Нет интерактивных элементов для самопроверки
- Нет поиска по контенту
- Нет визуализации прогресса и roadmap

---

## Целевое состояние

Интерактивная учебная платформа с:
- Удобной навигацией по разделам и статьям
- Трекером прогресса с сохранением в браузере
- Интерактивными quiz и flashcards
- Поиском по всему контенту
- Визуализацией roadmap и зависимостей между темами
- Системой повторения (Spaced Repetition)

---

## Технологический стек

| Компонент | Технология | Обоснование |
|-----------|------------|-------------|
| SSG | Astro | Zero JS по умолчанию, content collections, быстрый билд |
| Контент | MDX | Markdown + интерактивные React-компоненты |
| Стили | Tailwind CSS | Быстрая разработка, consistency |
| Интерактив | React (Astro islands) | Только там, где нужен (quiz, прогресс) |
| Хранение прогресса | localStorage | Без бэкенда, работает offline |
| Поиск | Pagefind | Генерируется на билде, не требует сервиса |
| Деплой | GitHub Pages | Бесплатно, CDN, автодеплой из GitHub Actions |

## Phase 1: Миграция контента

**Цель:** Перенести markdown в Astro content collections с типизированным frontmatter.

### Задачи

- [ ] Создать структуру `src/content/{section}/{article}.mdx`
  - `src/content/javascript/js-closures.mdx`
  - `src/content/typescript/typescript-generics.mdx`
  - и т.д. для всех ~100 статей
- [ ] Определить схему frontmatter (`src/content/config.ts`):
  ```ts
  const articleSchema = z.object({
    title: z.string(),
    section: z.enum(['javascript', 'typescript', 'react', ...]),
    description: z.string().optional(),
    order: z.number(),
    tags: z.array(z.string()).optional(),
    relatedArticles: z.array(z.string()).optional(),
  });
  ```
- [ ] Добавить frontmatter к каждой статье
- [ ] Мигрировать чеклисты из markdown в структурированный формат:
  - Вариант A: Оставить как markdown-списки, парсить на клиенте
  - Вариант B: Вынести в frontmatter как массив вопросов
- [ ] Настроить генерацию страниц из content collections
- [ ] Создать страницы разделов (`/javascript`, `/typescript`, ...)
- [ ] Создать страницы статей (`/javascript/closures`, ...)

### Структура контента

```
src/content/
├── config.ts                    # Схема frontmatter
├── javascript/
│   ├── _section.mdx             # Описание раздела
│   ├── js-data-types.mdx
│   ├── js-scope-hoisting.mdx
│   ├── js-closures.mdx
│   └── ...
├── typescript/
│   ├── _section.mdx
│   ├── typescript-generics.mdx
│   └── ...
├── react/
│   ├── _section.mdx
│   ├── react-hooks.mdx
│   └── ...
└── ...
```

### Frontmatter пример

```mdx
---
title: "Замыкания"
section: javascript
description: "Как работает closure, приватные переменные, каррирование, stale closures в React"
order: 3
tags: [closure, scope, hooks, react]
relatedArticles: [js-scope-hoisting, js-this]
questions:
  - Что такое замыкание и как оно работает под капотом
  - Почему внутренняя функция сохраняет доступ к переменным внешней функции
  - Как создать приватные переменные с помощью замыканий
  - Чем отличается каррирование от обычной функции
  - Как исправить вывод setTimeout в цикле с var
  - Почему модули можно рассматривать как замыкания
  - Как замыкания связаны с React-хуками
  - Что такое stale closure и как его избежать
---

# Замыкания

Замыкание — это функция, которая «помнит» переменные из лексического окружения...
```

### Результат

- Весь контент мигрирован в Astro content collections
- Типизированный frontmatter с валидацией
- Автоматическая генерация страниц разделов и статей
- Навигация между статьями работает

## Phase 3: Трекер прогресса

**Цель:** Сохранять прогресс прохождения вопросов в браузере.

### Задачи

- [ ] Создать React-компонент `QuestionCheckbox`:
  - Чекбокс рядом с каждым вопросом
  - Три состояния: не знаю (красный), частично (жёлтый), знаю (зелёный)
  - Анимация переключения
- [ ] Создать хук `useProgress`:
  - Сохранение в localStorage
  - Ключ: `progress:{section}:{articleId}:{questionIndex}`
  - Значение: `'unknown' | 'partial' | 'known'`
  - Синхронизация между вкладками (storage event)
- [ ] Компонент `ProgressSummary`:
  - Прогресс-бар на странице раздела
  - Статистика: "Пройдено 47/180 вопросов"
  - Круговая диаграмма по состояниям
- [ ] Главная страница с общим прогрессом:
  - Прогресс по каждому разделу
  - Общий прогресс (все вопросы)
  - Streak дней (опционально)
- [ ] Экспорт/импорт прогресса:
  - Кнопка "Скачать прогресс" → JSON файл
  - Кнопка "Загрузить прогресс" из JSON
  - Для бэкапа и переноса между устройствами

### Структура данных в localStorage

```ts
interface Progress {
  version: 1;
  answers: {
    [articleId: string]: {
      [questionIndex: number]: 'unknown' | 'partial' | 'known';
    };
  };
  lastVisited: {
    articleId: string;
    timestamp: number;
  };
  streak: {
    current: number;
    lastDate: string; // YYYY-MM-DD
  };
}
```

### Результат

- Пользователь может отмечать вопросы
- Прогресс сохраняется между сессиями
- Визуализация прогресса на всех уровнях
- Мотивация продолжать обучение

## Phase 5: Интерактивные элементы

**Цель:** Добавить инструменты для активного обучения.

### 5.1 Quiz-режим

- [ ] Компонент `QuizMode`:
  - Случайный вопрос из выбранного раздела
  - Раскрывающийся ответ (кнопка "Показать ответ")
  - Оценка: "Не знаю" / "Частично" / "Знаю"
  - Переход к следующему вопросу
- [ ] Режим "Мок-интервью":
  - Таймер на 30 минут
  - 10 случайных вопросов из разных разделов
  - В конце — статистика по ответам
- [ ] Фильтры:
  - Только вопросы из определённого раздела
  - Только вопросы с определённым тегом
  - Только вопросы, которые пользователь отмечал как "частично"

### 5.2 Flashcards

- [ ] Компонент `FlashCard`:
  - Карточка: вопрос на одной стороне, ответ на другой
  - Клик/свайп для переворота
  - Анимация переворота (CSS 3D transform)
- [ ] Режим "Колода":
  - Последовательный просмотр карточек
  - Оценка сложности ответа (Anki-подобная: Again, Hard, Good, Easy)

- [ ] Генерация карточек:
  - Из чеклистов статей (вопрос → краткий ответ из контента)

### 5.3 Интерактивные код-примеры

- [ ] Интеграция с Sandpack (CodeSandbox):
  - Редактируемые примеры кода прямо в статье
  - Мгновенный preview для React-компонентов
  - Кнопка "Открыть в CodeSandbox"
- [ ] Альтернатива: CodeHike (более лёгкий, без iframe)

### Результат

- Несколько режимов самопроверки
- Активное обучение вместо пассивного чтения
- Мотивация возвращаться к материалу

## Phase 6: Spaced Repetition System

**Цель:** Автоматизировать повторение сложных тем.

### Задачи

- [ ] Реализовать алгоритм SM-2 (упрощённая версия Anki):
  - Интервалы: 1 день → 3 дня → 7 дней → 14 дней → 30 дней
  - Множитель зависит от оценки (Again/Hard/Good/Easy)
  - Карточки, на которые ответили "Again", возвращаются в конец колоды
- [ ] Хранение данных в localStorage:
  ```ts
  interface FlashcardProgress {
    cardId: string;
    interval: number; // дней
    easeFactor: number; // множитель сложности
    repetitions: number;
    nextReview: string; // ISO date
    lastReview: string;
  }
  ```
- [ ] Страница "Повторить сегодня":
  - Список карточек, которые пора повторить
  - Счётчик: "12 карточек на сегодня"
  - Режим повторения с оценкой ответа
- [ ] Уведомления (опционально):
  - Browser Notification API
  - "У тебя 5 карточек на повторение"

### Результат

- Автоматическое планирование повторения
- Фокус на сложных темах
- Долгосрочное запоминание

## Риски и митигация

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Миграция контента займёт больше времени | Средняя | Высокое | Автоматизация скриптами, миграция частями |
| localStorage не хватает для данных | Низкая | Среднее | Использовать IndexedDB для больших данных |
